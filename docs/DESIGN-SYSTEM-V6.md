# WaBridge premium console — visual system v6

## Non-negotiable standards

WaBridge is an operations console, not a marketing landing page. It may take inspiration from contemporary SaaS visual language without copying another site's assets, layouts or unsupported capabilities.

1. **Single source of truth.** The production stylesheet is public/assets/wabridge-ui-v6.css, generated by tools/build-assets.php from the single authored public/assets/wabridge-design-v6.css. Legacy v2/v3/v4/v5 styles are not linked or packaged.
2. **Real browser review.** The Premium UI visual QA workflow renders a synthetic dashboard in actual Chrome at 1440x1000 and 390x844. It saves screenshots and checks rendered glass blur, font family, hero, KPI sizing, and horizontal overflow. Synthetic CI is not live Cloudways verification.
3. **Typography.** Locally hosted Inter WOFF2 normal 400, 600 and 700 under SIL OFL 1.1. Heading scale roughly 30–42px, panel headings 20px, body 14px, and meaningful metadata 10–12px. No Georgia or mixed serif typography in the admin experience.
4. **Spacing and components.** Predictable 8/16/24/32px spacing rhythm, 24px large surfaces, controls at least 42px high, visible focus, and uncluttered mobile reading order.
5. **Glass composition.** Tinted ambient background, translucent white surfaces with restrained border highlights and soft shadows, a single blur per container, opaque-enough table interiors, and reduced-transparency support. Blur by itself is not premium UI.
6. **Navigation.** One SVG-icon sidebar across all authenticated pages, with true active route, keyboard-accessible details groups, persisted desktop collapse, mobile drawer, Escape and backdrop close. Avoid random symbol characters as icons.
7. **Information architecture.** Overview: hero, honest gateway health, concise KPI tiles, linked sessions, message activity. Dedicated pages handle QR device pairing, sending, message logs, API credentials, Rust configuration and operational diagnostics. Do not put long configuration forms on Overview.
8. **Operational integrity.** Gateway HTTP acceptance is not WhatsApp delivery. Read/delivered badges require matching evidence. Mask recipients and never expose private credentials in activity UI.
9. **No patch layering.** Fix visual problems in the canonical source rather than append another stylesheet. Run browser screenshots at two viewports and inspect them before claiming improvement.
10. **Live sign-off.** After DigiOps deployment verify Cloudways Overview, Message Activity, Devices, Messaging and Gateway pages with a real logged-in session; also test the mobile drawer. CI does not prove live hosting rewrites, caches or authentication.

## Implementation index

- Canonical source: public/assets/wabridge-design-v6.css
- Browser artifact: public/assets/wabridge-ui-v6.css
- Shared shell/icons: src/ui-shell.php
- Sidebar interaction: public/assets/wabridge-console-v3.js
- Synthetic-only fixture: tests/visual-fixture.php (never packaged)
- Visual QA: .github/workflows/design-qa.yml
- Release tests: tests/dashboard-shell.php, tests/ui-shell-render.php and tools/check-release-package.php
- Typography assets: public/assets/fonts and the bundled SIL OFL license.

## Design direction

The marketing reference at wabridge.com/features emphasizes expressive typography and promotional composition. The WaBridge administrative console instead uses that level of polish with the information density, accessibility and truthful statuses needed for a production operational application.
